## Why build it this way

A portfolio is the one project every recruiter actually opens, so I wanted it to *be* the proof instead of just describing it. DANIEL_OS boots like an old computer: you can drag windows, type real commands in a terminal, read the live git log, sign the guestbook over ssh, or ask an AI about my work. For people short on time, recruiter mode collapses everything into clean rows with one click.

## Architecture

- **Next.js App Router + TypeScript** serves the pages, project write-ups (MDX) and OG images.
- **One source of truth:** `lib/profile.ts` holds every fact about me. The desktop, recruiter mode, the `ask` command and link previews all read from it, so nothing drifts out of date.
- **A vanilla-JS desktop** (`public/os.js`) handles windows, the terminal and the screensaver without a framework, which keeps the first load small.
- **APIs** for hits, guestbook, mail, Spotify now-playing and `ask` (Claude Haiku) run as serverless routes, rate-limited with Upstash Redis and falling back to memory locally.

## Drawing pixel art in code

None of the hobby scenes or the bear are image files. Each is a small function that paints a 64×40 (or 112×72) canvas at 12 frames per second:

- **One light source, three tones per material:** every surface gets a highlight, a base and a shadow, lit from the top left.
- **Sprites built from shapes:** the bear and the F1 car are assembled from discs, ellipses and spans on a grid, then an automatic pass draws a 1px outline wherever the sprite meets empty space. Changing a shape never means hand-fixing the outline.
- **Wheels and limbs drawn separately** so they can spin and wave independently of the body.
- **A fixed timestep** on `requestAnimationFrame` keeps animations steady and pauses them when the tab is hidden; clean mode and reduced-motion freeze them on a still frame.

## Testing

Playwright scripts click through the boot sequence, open every window, run terminal commands, capture each canvas frame-by-frame to check animations are continuous, and fail on any console error. The README screenshots are generated by the same scripts.
